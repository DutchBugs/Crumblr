| AG-012 | HIGH BEFORE REAL AGENT-DRIVEN SUBMISSION / NOT A SHADOW BLOCKER | Raised by Dev 1 (checked the actual `application/live_decision.py` flow, not a guess) while scoping the shared no-MT5 integration path (review 1.26 §7 item 3): `risk.policies.evaluate()`'s `PortfolioState.ledger` (`EquityLedger`) is stateful and per-process — `LiveDecisionOrchestrator` recovers it once via `risk.session.recover_session()` and holds/mutates it in memory across cycles, periodically persisting to `risk_session_states`, rather than reloading before every `evaluate()` call. If this Gateway's proposal path recovered and held its **own** independent copy of that same ledger in a separate process, an internal decision and an external-agent proposal could each pass the daily-loss/drawdown gate against a ledger that doesn't yet reflect the other's most recent trade — a lost-update race on one shared risk budget, invisible to either pipeline on its own. Two resolution paths, in order of preference: (1) route external-agent proposals into the *same running instance* that holds the canonical ledger, rather than a separate process reimplementing `recover_session()`; (2) if a separate process is architecturally necessary, re-recover the ledger fresh immediately before every `evaluate()` call instead of caching it in-process — not race-free without real DB locking, but avoids the worst staleness. **Not a blocker today**: `order_send` is unreachable regardless of which pipeline evaluates a proposal, so no real position can ever result from this gap — but it must be settled for real (most likely option 1) before `feedback.2.0` could ever treat agent-driven submission as real, not discovered live. `CapsuleStore.seal()` (content-derived `capsule_id`, `ON CONFLICT`-safe) and `evaluator.pretrade.evaluate()`'s currently-uncalibrated `intents_in_last_hour` check (`max_intents_per_hour: null` everywhere, F-024) are confirmed **not** to have the same issue today | OPEN — accepted as a shadow-mode-only limitation for the item 3 wiring, option 2 adopted (fresh `recover_session()` immediately before every Gateway-driven `evaluate()` call, never cached in-process); implemented in `agent_gateway/decision_path.py`, `tests/unit/test_agent_decision_path.py::TestAG012FreshSessionRecoveryEveryCall` | Option 1 (single shared risk-evaluation authority process) is designed and implemented before any agent-driven submission is treated as real |
